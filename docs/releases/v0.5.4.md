# Tote 0.5.4

Fixes pasting the DeepSeek Harness startup URL into its local-service pane.

## What changed

- Clicking the startup URL field keeps keyboard focus in the field. Returning to Tote after copying a URL also preserves its focus and caret.
- A **Paste URL** button reads the clipboard into the field. Select **Connect URL** or press Enter to connect; pasting alone does not navigate.
- Clipboard failures and an empty clipboard have visible messages. Startup tokens remain transient and are not saved in provider settings or workspace layouts.

## Upgrade

Use **Settings → About → Check for updates → Download → Install** on Linux AppImage. The viewer reconnects to the existing background host and agent sessions; this fix does not require a host restart. Android receives versionCode 16 through its existing updater, with no Android behavior changes and the same production signing identity and lineage. Wire protocol v1 is unchanged.

## Verification and limits

The provider UI regression exercises real mouse focus, window reactivation, text insertion, clipboard IPC success/failure, Enter submission, session-cookie exchange and token non-persistence. CI additionally exercises the native paste shortcut with its disposable clipboard. The release pipeline validates desktop/mobile tests, packaged PTYs, production Android signing and artifact hashes. Local tests do not read or replace the user's clipboard.

Physical phone testing remains deferred; this desktop UI fix makes no new claims about phone-specific behavior.
