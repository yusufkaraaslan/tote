# Tote 0.5.0 — release candidate notes

This version is prepared in source. These notes do not mean a signed release has been published.

Desktop and Android now use one release version. This release includes safer configuration writes and recovery, shared-layout conflict handling, synchronized terminal dimensions and mobile colors, bounded remote output with reconnect/replay, and desktop/Android diagnostics with reviewed exports.

Settings → About on desktop and Updates on Android can check the public GitHub release endpoint on demand. Tote does not install updates or restart automatically. Desktop delays its update download action while any host terminal is alive; phone drafts must be saved or cleared before following an update link. Finish desktop agents and save documents before quitting to replace the app. Host processes still stop when desktop Tote quits; independent background hosting is tracked in #6.

Wire protocol v1 remains compatible with earlier Tote hosts/viewers. App version differences are reported without rejecting otherwise compatible sessions. Feature support is negotiated separately: older hosts may lack shared layout revisions, output acknowledgements or diagnostics. A wire protocol mismatch refuses connection with update guidance.

Release packaging produces Linux AppImage/deb/pacman, a macOS DMG for the runner's native architecture, Windows x64 NSIS, and an Android APK. The bundle includes SHA256SUMS and release-manifest.json. Preview builds have no desktop publisher identity (macOS uses ad-hoc signing for launch) and a debug-signed Android APK; they are separate from production signing. Signed tag builds create a **draft**, which remains excluded from update notices until published.

Signing credentials and physical-device verification must be completed before publishing. Reuse the Android signing identity for upgrades: a different key cannot replace an existing installation. Do not uninstall a working installation just to bypass a key mismatch; preserve its local data and resolve the signing configuration first.
