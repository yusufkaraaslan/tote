# Tote 0.5.0

Tote 0.5.0 brings background terminal sessions, verified in-app updates for Linux AppImage and Android, and fixes for terminal flicker, scrollback and colors. Production downloads are Linux x64 AppImage, Debian and Arch packages, plus an Android 13+ APK. macOS and Windows remain preview-only.

## What changed

- Terminal sessions run in a separate background host and survive closing, quitting or replacing the desktop viewer. Settings → About shows host status, explicit start/stop controls and optional sign-in startup. Reboot, sign-out and explicitly stopping the host still end its terminals.
- Linux AppImage and Android can check for a stable release, download it with size/checksum verification, and install after explicit confirmation. Installation protects unsaved documents, layouts and phone drafts. Android also verifies the production signing identity and upgrade lineage before opening the system installer. Nothing installs automatically.
- Shared terminals preserve the host's grid across differently sized viewers. Parsing, resize and replay stay ordered; slow or disconnected viewers reconnect without pausing the shared PTY or retrying input.
- Fixed scrollbars repeatedly appearing and disappearing at fractional pane sizes. Terminal redraws no longer undo an in-progress scroll. Desktop history now retains 5,000 lines, matching the host and Android.
- New Codex profiles use `--no-alt-screen` to preserve terminal history. Existing custom profiles are retained; add that flag to the Codex profile's `args` and start or resume in a new terminal to use it. Already-discarded terminal history cannot be recovered.
- Fresh PTYs advertise truecolor and drop a launcher's inherited `NO_COLOR` setting. Android's wrapped reading view preserves ANSI/256-color/truecolor and text styles.
- Configuration saves are atomic, retain a validated previous version, and recover damaged files visibly. Shared layouts use revisions and explicit conflict resolution while protecting unsaved documents.
- Desktop and Android diagnostics provide a reviewed, bounded export without terminal output, private paths, addresses, tokens or cookies.

## Upgrade

Install this first updater-capable release manually. Older clients can open the release page; future compatible releases can use the new download/install flow. Package-managed Linux installations continue to use `pacman` or `apt` rather than replacing managed files in-app.

Save documents and provider drafts before replacing the desktop viewer. Its background host keeps a separate immutable runtime copy, so replacing the viewer does not upgrade the running host. To apply the new host-side color behavior, finish agents, stop the old host and start the new runtime. Existing agents retain their original launch environment.

Android requires **Android 13 or newer (API 33)**. The production APK uses the pinned dedicated signing identity and approved rotation from 0.4.0. Install over the existing app; do not uninstall to work around a signature error. The official APK uses versionCode 12, above the private 0.5.0/code 11 rehearsal builds. Those rehearsal clients already report version 0.5.0, so replacing them with this official APK is a manual installation.

Wire protocol v1 remains compatible with earlier hosts/viewers. Older hosts may lack newer layout, output-acknowledgement or diagnostics capabilities; those features retain their compatibility fallbacks.

## Verification and recovery

The release includes `SHA256SUMS` and a production `release-manifest.json`. Android APKs use the production certificate and signing lineage; Linux trust is the fixed GitHub HTTPS origin and checksums, not an independent Linux publisher certificate. Preview packages are outside the production update channel.

Automated checks cover desktop logic on Linux/macOS/Windows, real renderer regressions, Android native tests/lint, packaged PTYs and background-host replacement, and Android signing/upgrade rehearsals. The maintainer reported the patched Linux installation and physical Android app working on November 17. That general acceptance does not claim every provider login, sign-in/power, voice or phone permission/cancellation scenario was individually verified; see the [verification record](https://github.com/yusufkaraaslan/tote/blob/v0.5.0/docs/release-readiness.md).

Keep configuration backups and the previous release for recovery. Finish agents before a host rollback; older versions are not guaranteed to understand newer saved configuration. See [update operation and recovery](https://github.com/yusufkaraaslan/tote/blob/v0.5.0/docs/self-updates.md).
