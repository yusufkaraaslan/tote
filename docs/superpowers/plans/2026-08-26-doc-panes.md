# Doc Panes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clicking a file in the workspace tree opens it as a pane — text/code editable, markdown rendered, images and PDFs viewable — instead of the modal `<textarea>`.

**Architecture:** A new tiling leaf kind `'doc'` whose ref is a persisted *instance* (`{id, path, mode}`) rather than a path, so a click can retarget a pane without editing the tree. One IPC channel `workspace:readDoc` classifies and reads. Markdown is parsed by a new dependency-free pure module (`src/renderer/markdown.js`) into tokens and built into DOM with `createElement` — never `innerHTML`.

**Tech Stack:** Plain CommonJS (main) and vanilla browser JS (renderer). No bundler, no TypeScript, no test framework — the hand-rolled `describe`/`test` harness in `scripts/`.

**Spec:** `docs/superpowers/specs/2026-08-26-doc-panes-design.md`

## Global Constraints

- **No new runtime dependencies.** The markdown parser is written in this repo.
- **Never `innerHTML`.** Rendered markdown is built with `document.createElement`. A `<script>` in a README must render as literal text.
- **Hrefs filtered at parse time** to `http:`, `https:`, `mailto:`, and workspace-relative. `javascript:`/`data:` degrade to plain text, never an anchor.
- **All file access goes through `WorkspaceManager.resolveSafe(rel)`.** The renderer only ever passes relative paths.
- **Pane elements are created once and never reparented.** A doc pane rebuilds `.pane-body`; the element itself never moves.
- **Adding a capability = three edits:** `ipcMain.handle` in `main.js` → wrapper in `preload.js` → call site in `app.js`.
- **Leaf kind is `'doc'`, never `'file'`** — `'files'` (the dock) already exists.
- Caps: text/md 2 MB (`MAX_READ_BYTES`), image 25 MB, PDF uncapped (never copied).
- `npm test` must stay green and gains a third suite: `node scripts/test-doc.js`.

```js
const IMAGE_EXT = new Set(['.png', '.jpg', '.jpeg', '.gif', '.webp', '.bmp', '.ico', '.svg']);
const MD_EXT = new Set(['.md', '.markdown']);
const MAX_IMAGE_BYTES = 25 * 1024 * 1024;
const MIME = { '.png': 'image/png', '.jpg': 'image/jpeg', '.jpeg': 'image/jpeg',
  '.gif': 'image/gif', '.webp': 'image/webp', '.bmp': 'image/bmp',
  '.ico': 'image/x-icon', '.svg': 'image/svg+xml' };

// How a file is shown. SVG is deliberately an image even though it is in
// TEXT_EXT: readDoc fills in `text` too, which is what gives it both modes.
function docKind(name) {
  const ext = path.extname(name).toLowerCase();
  if (MD_EXT.has(ext)) return 'md';
  if (IMAGE_EXT.has(ext)) return 'image';
  if (ext === '.pdf') return 'pdf';
  if (TEXT_EXT.has(ext)) return 'text';
  return 'binary';
}
```

- [ ] **Step 2: `openDoc`**

```js
// The single entry point for showing a file. Reuse is the default: clicking
// another file retargets the pane you are already looking at, so the tree is
// never edited and the split ratio survives.
async function openDoc(rel, { newPane = false } = {}) {
  const S = tiles(), V = wsViews();
  const open = T.leaves(S.tree).filter((l) => l.kind === 'doc');
  const already = open.find((l) => (V.docs.find((d) => d.id === l.ref) || {}).path === rel);
  if (already) return focusPane(already.id);
  const target = newPane ? null : (open.find((l) => l.id === S.focus) || lastFocusedDoc(open));
  if (target) return retargetDoc(target.ref, rel);
  const doc = { id: newId('d'), path: rel, mode: 'view' };
  V.docs.push(doc);
  openPane(T.leaf(newLeafId(), 'doc', doc.id));
}
```

`retargetDoc` refuses on a dirty pane unless `confirm()` says otherwise, then sets `doc.path`, clears the runtime entry and calls `loadDoc`. `lastFocusedDoc` reads a `state.docFocusOrder` array pushed to by `focusPane`.

- [ ] **Step 3: `loadDoc` and the text body**
