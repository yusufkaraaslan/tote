# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tote is an Electron desktop app: web LLM tabs (Kimi, Claude, ChatGPT, …) + a shared **workspace** folder pane + docked CLI-agent terminals (Claude Code, Kimi CLI, Codex, …). The organizing idea is **spaces**: one Global workspace plus project workspaces. The *active* space is the routing context for everything — web-tab downloads land in `<space>/inbox/<provider>/`, native-app downloads are bridged into `<space>/inbox/_desktop/`, and every new terminal spawns with `cwd = <space>`. A space may also be **remote** — a project on another machine reached over ssh (typically Tailscale SSH) — and then its files pane, doc panes and agent terminals all run there.

The project was renamed from OmniHub to Tote; `migrateFromOmniHub()` in `main.js` moves the old userData folder, renames `omnihub-*` partition dirs and `installer.js` upgrades the `omnihub-workspace` MCP key — keep that migration until users have moved. Plain JavaScript everywhere (CommonJS in main, vanilla browser JS in renderer). No bundler, no TypeScript, no linter. The only tests are `npm test` → `scripts/test-layout.js` (the pure tiling engine), `scripts/test-scratch.js` (temp-space naming, the delete guard, promote, sweep), `scripts/test-doc.js` (the markdown parser and the extension→kind map), `scripts/test-npmfix.js` (the wizard's npm-output detectors and prefix-fix guards) `scripts/test-remote.js` (remote spaces: shell quoting, the commands sent over ssh, remote path containment, the tree parser, and the ssh/Tailscale output detectors) and `scripts/test-watch.js` (what the tree walks and the watcher binds — the descriptor budget), all dependency-free; everything else is verified by running the app. `AGENTS.md` and `README.md` also describe the project, and `archlens.model.yaml` is a tracked component/method model of `src/` — keep all four in sync when changing architecture.

## Commands

```bash
npm install            # postinstall runs scripts/copy-vendor.js: vendors xterm assets + chmod +x node-pty's spawn-helper
npm start              # electron .
npm test               # test-layout.js (tiling engine, 60) + test-scratch.js (temp spaces, 42) + test-doc.js (markdown, 54) + test-npmfix.js (wizard installs, 20) + test-remote.js (remote spaces, 126) + test-watch.js (tree/watcher ignores, 10)
npm rebuild node-pty   # if terminals are disabled ("node-pty unavailable" toast); needs a C++ toolchain
./scripts/install.sh   # prereq checks + npm install + npm start

npm run install:mac    # test + build + install to /Applications (see below)
npm run pack           # electron-builder --dir (unpacked build, fast smoke test)
npm run dist           # installer for current platform → dist/
npm run dist:linux | dist:mac | dist:win
```

`npm test` is the *only* automated check and it covers `src/renderer/layout.js`, `src/renderer/markdown.js`, `src/renderer/npmfix.js`, `src/main/scratch.js` + the `WorkspaceManager` temp-space methods, `src/main/sshfix.js`, `WorkspaceManager`'s tree/watch ignores, and `docKind` — everything else is verified by running the app. The harness is a hand-rolled `describe`/`test` pair in each script with **no filter flag**: there is no "run one test" command, so run the whole file and read the grouped output (`✓`/`✗` per case, non-zero exit on failure). `main.js` takes a single-instance lock — if `npm start` appears to do nothing, an instance is already running and just got focused; quit it first. That lock is also why `scripts/install-macos.sh` (`npm run install:mac`) exists rather than a plain `pack` + copy: Tote docks agent terminals, so an upgrade is usually run *from inside Tote*, and `npm run pack` starts by deleting the very bundle that process is executing from. The script therefore stages the build in `dist-next/`, never touches the running bundle, walks up its own process tree to find out which bundle that is, and — because the new copy cannot start while the old one holds the lock — leaves a detached watcher that reopens the installed app once the old one quits. The script's "is the target running" guard uses **`pgrep -a`**: pgrep excludes itself and all of its ancestors by default, so from a terminal docked inside Tote the plain form can never see the very app being upgraded — the deferral is skipped and a live bundle gets renamed out from under it. Runtime config lives in `<userData>/config/` (Settings → "open config folder"; `<userData>` = `~/Library/Application Support/Tote` on macOS, `~/.config/Tote` on Linux, `%APPDATA%\Tote` on Windows), and the Global workspace defaults to `~/tote/workspace`.

## Architecture

Three Electron layers, strictly separated:

- **`src/main/`** — all Node/OS access.
  - `main.js` — window, per-provider `session` setup (`will-download` hook), Downloads-folder bridge, local-service starter (`ensureLocalService`, e.g. DeepSeek Harness web UI), native-app detection/launcher, and **every `ipcMain` handler**.
  - `workspace.js` — `WorkspaceManager`: spaces registry, `resolveSafe`, tree, text read/write, `ingest()`, chokidar watchers (workspace tree + `~/Downloads`).
  - `config.js` — `ConfigStore`: on first run copies `config/*.json` into `<userData>/config/`, then reads/writes only the userData copies. `views.json` holds per-workspace open web tabs *and* the space's groups (`{ [wsId]: { tabs: [{id, providerId}], groups: [{ id, name, tree, focus, zoom }], activeGroup, filesRatio } }`). Two migrations run on first read and must both stay: the legacy `layout` key becomes a tree, and a single `tiling` object becomes `groups[0]`.
  - `ptyManager.js` — node-pty sessions keyed by numeric id; streams `pty:data`/`pty:exit` back to the `sender` webContents. `launch()` is the one place a pty is created and takes optional `onData`/`onExit` so the main process can observe a session it is also streaming to the renderer.
  - `sshfix.js` — **pure**: shell quoting, every command sent to a remote shell, remote path containment, the tree/stat/probe parsers, and the ssh/Tailscale output detectors. No fs, no child_process, no electron.
  - `remote.js` — `RemoteConn` (one multiplexed ssh connection per remote space, the state machine, the one interactive pty that may authenticate) and `RemoteFs` (the same file-op surface as the local half of `WorkspaceManager`).
  - `installer.js` — setup-wizard backend: system checks, Claude Desktop MCP binding (`claude_desktop_config.json`, with `.bak-<ts>` backup), generic MCP snippet.
- **`src/preload/preload.js`** — `contextBridge` exposing `window.tote`. This is the *only* API surface the renderer has. Wrapper names differ from IPC channel names (`tote.tree()` ↔ `workspace:tree`, `tote.ptyRun()` ↔ `pty:run`) — grep preload.js to map one to the other.
- **`src/renderer/`** — `index.html` + `app.js` (single file, one `state` object, section-commented) + `styles.css`. Uses `<webview>` tags for provider tabs and xterm.js for terminals. CSP is `script-src 'self'` — no inline scripts, no CDN; third-party JS must be vendored via `scripts/copy-vendor.js`.

### Invariants that span files

- **Active workspace is resolved at call time, never cached.** Every download handler, bridge callback, and `pty:spawn` calls `workspace.getRoot()` / `workspace.inboxDir()` when the event fires, so switching spaces re-routes instantly. Don't capture the root in a closure.
- **All workspace file access goes through `WorkspaceManager.resolveSafe(rel)`** (path-escape guard). Renderer only ever passes relative paths. `resolveSafe` is local-only and stays synchronous; a remote space goes through `sshfix.remoteResolve(root, rel)`, the same containment check built on `path.posix` (the remote is POSIX even when Tote runs on Windows, and a backslash there is a filename byte, not a separator).
- **Session partition names must match in two places**: `partitionFor()` in `main.js` and the `partition` attribute set in `ensureWebview()` in `app.js` (`persist:tote-<providerId>`). The `will-download` interception only works because both agree.
- **Adding a capability = three edits**: `ipcMain.handle`/`ipcMain.on` in `main.js` → wrapper in `preload.js` → call site in `app.js`. Never enable `nodeIntegration` or weaken `contextIsolation`.
- **Providers, CLI profiles, workspaces, apps, settings are data, not code** — defaults in `config/*.json`, live copies in userData. Add entries there rather than hardcoding. Note: editing `config/*.json` does **not** affect an existing install (the userData copy wins); delete the userData file to re-seed when testing default changes.
- **Terminals must stay real PTYs** (node-pty). Piping through `child_process` breaks TUI agents. `pty:run` (wizard installs) and `pty:spawn` (agent tabs) both go through `PtyManager`. A *remote* terminal is still a real local pty — it just has `ssh -tt` in it, so node-pty, xterm, SIGWINCH on resize, the Shift+Enter handler and the scrollback keys are all untouched: ssh is transparent to a tty. It rides the space's master socket and goes through the **remote** login shell for exactly the reason the local one does. `pty:run` and `cli:check` must follow the machine the agent will actually run on — `cli:check` over ssh for a remote space, `localCwd()` for the wizard's installs, which stay local.
- **CLI profiles carry an `install` command** (`npm i -g <pkg>`) used by the wizard's one-click install; keep package names accurate. An empty `command` means "user's default shell"; optional `hint` is printed (yellow) into the terminal at spawn. DeepSeek Harness is deliberately *not* a CLI profile (it only has `web`/`headless` modes) — it's the `dsh-local` web provider.
- **Setup wizard is split**: backend in `installer.js` + IPC in `main.js` (`setup:*`, `conn:*`, `pty:run`); UI in the "setup wizard" section of `app.js` (`wiz*` / `renderWz*` functions, `wizTerm` xterm for install output) and `#wizard-modal` in `index.html`. It auto-opens while `settings.setupDone === false`.
- **Wizard installs self-heal, each mend at most once.** `runWizardInstall` buffers the run's output (`wizBuf`, filled beside the `wizTerm.write` in `onPtyData`) and on exit consults `src/renderer/npmfix.js` — pure detectors dual-exported like `layout.js`, covered by `scripts/test-npmfix.js`. npm ≥ 12's blocked-install-scripts warning → re-run with the `--allow-scripts=…` value npm itself suggested (a blocked script means a native dep silently didn't build); `EACCES` from a root-owned global prefix (distro npm under `/usr`) → `setup:fixNpmPrefix` appends `prefix=<home>/.local` to `~/.npmrc` and the install re-runs. The write happens **only** when `prefixPlan` approves: POSIX, prefix genuinely unwritable, no `prefix=` already in `~/.npmrc`, and `~/.local/bin` on PATH — otherwise the wizard prints the manual fix instead. `installer.js` requires `npmfix.js` across the layer boundary; that's fine for pure modules only. The `triedPrefix`/`triedScripts` flags are the loop bound — keep them.
- **Native apps are launched, never embedded.** `launchApp()` special-cases `kind: 'claude'` to write the MCP binding before spawning; other apps rely on the Downloads-folder bridge (`applyBridgeSetting`, toggled by `settings.bridgeDownloads`). `detectApps()` seeds `apps.json` from `KNOWN_APPS` only while the list is empty — once a user has any entry it never re-seeds.
- **Exactly one function deletes user files.** `WorkspaceManager.discardTemp()` is it, and it refuses unless the space carries `temp: true`, its resolved path sits strictly inside the resolved scratch root (`settings.scratchRoot`, default `~/tote/scratch`), and it is not the last space. The guards live in that function, never at a call site — `sweepTemp` and the `workspaces:discard` handler both go through it. `remove()` keeps its own contract: it unregisters a space and never touches the disk. Paths are compared through `realpathDeepest()`, which resolves as far down as the path exists: a folder deleted by hand, or a promotion target that does not exist yet, still has to be comparable with a realpath'd root, and any ancestor can be a symlink (`/var` → `/private/var` on macOS). Pure decisions — slug, default name, collision suffix, containment, expiry — live in `src/main/scratch.js` and are covered by `scripts/test-scratch.js`; `npm test` now runs the layout suite **and** that one.
- **Temp spaces are spaces.** They differ by two fields — `temp: true` and `lastUsed` (stamped in `setActive`) — so downloads, inbox routing, terminal `cwd`, watchers and `resolveSafe` need no special cases. Their ids are made unique against the registry rather than by timestamp alone: unlike a folder pick, two temp spaces can be created inside one millisecond. `promote()` moves the folder (copy+remove across volumes) and clears both fields, keeping the id so `views.json` — tabs, groups, layout — survives; it guards on the resolved target but stores the folder the user picked, as `add()` does. The sweep runs at launch only, never mid-session: `scratchDays` defaults to 7 (read with `?? 7`, since the userData copy of `settings.json` wins on existing installs) and `<= 0` disables it.
- **A space is remote iff it carries a `host`, and every local path rule inverts for one.** The registry entry is just `{id, name, path, host}` — `path` is on the *other* machine and stays exactly as typed. Three traps, all guarded and all worth keeping: `expandTilde` must never touch it (`wsPath()`), or a remote `~/proj` silently becomes this machine's home; `ensureInbox()` must not `mkdir` it, or booting with a remote space active creates the remote's path locally; and `discardTemp()` — the one function that deletes user files — refuses a remote space outright before its guards run, because every one of them compares local realpaths. `promote()` refuses too. `getRoot()` returns the remote path; `localCwd()` is what a pty may actually be given.
- **File ops dispatch on the backend, and the IPC layer cannot tell the difference.** `WorkspaceManager.backend()` returns a `RemoteFs` or null, resolved per call and never cached, exactly as `getRoot()` is. Each public file op is `async` and opens with a two-line delegation; the local body below it is untouched and still synchronous. `RemoteFs` returns the *same shapes* as the local half — that is why `ipcMain.handle('workspace:tree', …)` and the whole renderer needed no changes. It is handed the local `FILE_META` (`docKind`, `isTextFile`, `extOf`, `MIME`, the caps) rather than duplicating them, which is what keeps a remote tree node and a remote doc pane agreeing about a file's kind for the same reason the local ones do.
- **Every remote path crosses a shell, so quoting has exactly one owner.** `sshfix.shq()`, applied once, by the command builders in `sshfix.js`. Nothing else in the app may concatenate a path into a remote command string — that is the whole reason the command builders live in the pure module and are covered case by case in `scripts/test-remote.js`, hostile filenames included. `shqPath()` is the single exception, used only by the connect probe so a leading `~` expands on the *remote*; the probe reports the absolute path back (`TOTE_ROOT=`), that is what gets stored, and `shq` alone suffices from then on.
- **Exactly one thing may authenticate, and it is never a file operation.** Tailscale SSH's check period expires on a timer, so re-auth is an *ambient* condition any operation can hit at any moment — not a setup step. Every non-interactive op runs with `BatchMode=yes` and a short `ConnectTimeout`, and hands failure to `RemoteConn`, which owns the one interactive pty that can answer a host-key question, a passphrase, or a "visit this URL". `run()` retries once behind `silentConnect()` **only on ssh's own exit code 255** — any other code came from the remote command, and re-running it would apply a non-idempotent operation twice.
- **`BatchMode` is not what stops an op from hanging — a timeout and a sniffer are.** This was a real bug, found against a live tailnet: `BatchMode` suppresses ssh's *own* prompts, and `ConnectTimeout` bounds the *handshake*. Tailscale's check is served by the remote **after** the connection is up, so neither applies — ssh holds an open session indefinitely while `# To authenticate, visit: …` sits on stderr. A remote `tree`/`readDoc`/save/poll would spin forever, and the poller's `busy` flag would stick, killing polling permanently. So `exec()` in `remote.js` takes **`timeout`** (`OP_TIMEOUT`, the backstop) and **`abortOn`** (`sshfix.needsHuman`, which fires the moment the banner appears — measured at 151 ms against the real host). The partial output is kept precisely because it carries the URL, so the abort classifies into the normal `auth` state and the banner offers the login link. **The sniffer reads stderr only**, never stdout: that is where the banner lands (verified — stdout stays empty), and scanning stdout would let a file that merely *documents* a login URL abort its own read, besides string-decoding every chunk of a 25 MB image for nothing. The interactive `connect()` pty is deliberately left unbounded — blocking there is the entire point.
- **The master socket's lifetime is what sets how often the user re-authenticates.** New channels over an already-authenticated master do not re-trigger Tailscale's check; only a new connection does. Hence `ControlPersist=yes` (not a few minutes) plus `ServerAliveInterval`, one socket per space under `<userData>/ssh/`, named by a hash because a unix socket path has ~104 bytes to work with. **That path contains a space on macOS** (`~/Library/Application Support/Tote`), and `-o` takes a config *line* which ssh splits on whitespace — so the value is double-quoted by `ctl()` in every builder, unconditionally rather than only when a space is present. Unquoted, every single remote operation dies before connecting with `keyword controlpath extra arguments at end of line`. It deliberately **outlives Tote** — quitting must not tear it down, because that is what lets a relaunch reconnect with no browser round trip at all.
- **The connect session is a pane, not a wizard.** Registering a remote space and re-authenticating an existing one are the same code path (`RemoteConn.connect()`), because the second happens far more often than the first and must not interrupt whatever else is open. It streams into an ordinary term leaf via `PtyManager.launch()`, which tees the output to the renderer *and* to `RemoteConn`, so the main process stays the authority on connection state while the user watches. The auth URL is opened once per attempt (`triedAuth`, the same loop bound as `triedPrefix`/`triedScripts`) and also offered as a button. State is pushed to the renderer as `remote:state`; the space chip badges from *every* space, since a connection that needs you may not be the one you are looking at.
- **A disconnected remote shows a banner, never an empty tree.** An empty tree reads as "this project has no files", which is a lie a user may act on, so `refreshTree()` leaves `state.treeData` alone on failure and `#remote-bar` carries the reason and the one action that fixes it. Detectors in `sshfix.js` are what turn ssh's output into that reason, each covered by real captured output — including `noSuchUser`, which must outrank `socketDead` in `classify()` because Tailscale SSH maps the tailnet identity onto a *local* account and failing that lookup also closes the connection ("connection dropped" would send the user chasing the wrong thing; the fix is `user@host`).
- **A remote space polls; it never binds chokidar.** There is no inotify to reach and no descriptor budget to blow. `watchRemote()` asks the remote to hash a listing (`fingerprintCommand` → `cksum`), so the reply is one line however big the project is, and only for the active space, only while its connection is `up`, and never stacking a second poll on a slow link. The fingerprint covers **mtimes as well as names** on purpose (`ls -ld` per file, batched through `xargs`): the whole point of a remote space is an agent editing files in a terminal, and an open doc pane learns about that edit only through this tick. `find -printf` would be one pass instead of two but is GNU-only, and the remote may be macOS — which is also why `stat` is tried as `-c %Y` then `-f %m`, and why the byte count is stripped with `tr` (BSD `wc -c` left-pads, and command substitution turns that into `TOTE_SIZE= 6`).
- **Remote spaces borrow local disk for the three things that need a real path.** A `<webview>` cannot be pointed at another machine, so a remote PDF is cached under `<userData>/remote/<hash>/` keyed by mtime (a changed file is a different file, so staleness needs no bookkeeping) — same for "send to active tab". Chromium can only download locally, so `will-download` stages into `stagingDir()` and `ingestInto()` pushes the finished file up over the same master; the space is fixed when the download *starts*, which is the one place the active space deliberately does not decide. That push is **ssh + `cat >` with the file streamed into stdin, deliberately not `scp`**: scp's remote path is shell-expanded by the pre-9.0 backend and passed literally by the SFTP one, so a download called `My Report (1).pdf` breaks whichever way you quote it. Going through ssh puts the target back under `shq()` like every other remote path, and streaming means a large download never passes through memory. And there is no remote wastebasket, so `trash` moves into the space's own `.tote-trash/` — never `rm`.
- **Workspace watcher must be re-armed on every active-space change.** `workspace.watch()` binds chokidar to the current root; every IPC handler that changes the active workspace (`workspaces:add/setActive/remove`) calls it again. A new handler that switches spaces must do the same or the tree stops refreshing.
- **The watcher has a file-descriptor budget, and blowing it breaks terminals, not the tree.** chokidar 4 dropped its fsevents dependency, so on every platform it falls back to `fs.watch` and opens **one descriptor per watched path**. A workspace carrying a big generated cache drags the main process to its `RLIMIT_NOFILE`; the first thing that fails afterwards is pty allocation, so node-pty returns a child with no controlling tty and Claude Code (and every other TUI agent) exits code 1 printing nothing. A Godot project did exactly this: `.godot` held 5k import-cache files, the process sat at ~11.6k open fds, and every agent terminal died instantly while the file tree looked fine. Three defences, keep all of them: `IGNORE` lists generated caches by name (`node_modules`, `.git`, `.godot`, `__pycache__`, `Pods`, …); `watchPlan()` counts watchable paths level by level and lowers the watch depth until it fits `WATCH_BUDGET`; and `watch()` **awaits the old watcher's `close()` before binding the new one**, because it is re-armed on every space switch and fire-and-forget held both sets of descriptors open across exactly the moment the process was running out (a generation counter, `watchGen`, means only the newest arm installs a watcher when a user clicks through spaces faster than a close resolves). `WATCH_BUDGET` is deliberately far below the ceiling (1500) rather than near it: webview partitions, ptys and the download bridge all spend from the same pool. Never trust `IGNORE` alone — the next project type brings a cache dir nobody listed, which is what the budget is for. When adding a cache dir to `IGNORE`, remember it also hides it from the files pane (correct for generated output, wrong for source).
- **A generated dir whose name is ordinary gets ignored by context, not by name.** Unity is `.godot` again at ten times the size — `Library/` alone holds ~50k files, and a space with two Unity projects in it bound 3.9k watch descriptors, walked 17.9k tree nodes per watcher tick, and left every terminal after the first showing `[process exited with code 0]` with no output at all. But `Library`, `Logs`, `Temp` and `obj` are names real source directories have, and `IGNORE` matches a basename *anywhere*, so putting them there would silently empty the files pane for somebody's hand-written `Library/`. Hence `IGNORE_UNITY` plus `skipper()`: the one `(dir, name) => skip?` predicate shared by `tree()`, `watchPlan()` and the watcher's `ignored`, which prunes those names only inside a directory that is actually a Unity project (`Assets` + `ProjectSettings` siblings — the same pair Unity itself looks for) and memoizes that disk test per directory. The watcher's `ignored` also has to exempt the root itself (`p !== root`), or a space whose own folder is called `out` or `Logs` watches nothing. Measured on the space that broke: 3874 → 465 descriptors, 17.9k → 463 tree nodes, 265 ms → 33 ms to arm. A *remote* space still gets the name-only list, since `find -prune` cannot ask about a sibling cheaply — it costs no descriptors there, only a slower `find`.
- **Descriptor exhaustion shows up as a terminal that exits 0, printing nothing.** Worth recognising, because nothing in the message points at the watcher: with the main process near its limit node-pty's helper cannot make the pty the child's controlling terminal, so the shell is left with no tty in its foreground process group, reads EOF and exits 0 — and node-pty announces that exit while the orphaned shell is *still running*, holding a tty of its own. (An agent that reads its own tty, like Claude Code, exits 1 instead.) `launch()`'s `onExit` therefore reaps (`proc.kill()`, ESRCH-safe) rather than only forgetting the session, so an orphan cannot outlive its pane. node-pty also never releases the pty master fd on exit — `destroy()`, `end()` and `kill()` were all measured to make no difference — which costs one descriptor per terminal ever opened; small next to the watcher, but it is why the budget above is not set close to the ceiling.
- **"Send to active tab" is best-effort DOM injection.** `tab:sendFile` takes the webview's `getWebContentsId()`, base64s the file (≤15 MB) and `executeJavaScript`s a `File` into the page's `input[type=file]` (fallback: synthetic drop). It only works after the webview has been created/attached, and it will break silently when a provider changes its upload markup.
- **Webview popups stay in-app.** `web-contents-created` allows every http(s) popup as a child window so it shares the provider's session partition — OAuth (Google/GitHub login) only works if the cookies land in that partition. Never route login popups to the system browser. Only non-web schemes go external.
- **UA must stay truthful.** `chromeUA()` takes Electron's real UA and strips only the `Electron/…` and `Tote/…` tokens. Hardcoding a UA with a different Chrome version/platform makes Cloudflare-fronted sites (claude.ai) render blank.
- **A GUI launch has a minimal PATH.** Started from Finder/Dock/`.desktop`, the app only gets `/usr/bin:/bin:/usr/sbin:/sbin` — no `npm`, no version-manager shims (fnm/nvm/asdf/volta), nothing in `~/.local/bin`. It works in dev only because `npm start` inherits the terminal's PATH. Two defenses, keep both: `adoptLoginShellPath()` in `main.js` reads the real PATH from `$SHELL -l -i` once at startup (fixes `cli:check`, `installer.js`'s `cmdVersion`, `ensureLocalService`), and `shellCommand()` in `ptyManager.js` runs every profile as `$SHELL -l -i -c 'exec <cmd>'` so each terminal resolves its own live env. Terminals can't use the startup snapshot — fnm builds a per-shell bin dir and can switch node version by directory. Never go back to exec'ing `profile.command` directly on POSIX.
- **The environment Tote was opened with is not the one it may hand to children.** It gives `process.env` to every child it spawns — each pty, the wizard's installs, `cli:check`, local services — so anything ambient at launch is replicated into every terminal for the life of that instance. That bites when the thing that opened Tote was itself a CLI agent session: `npm run install:mac` is normally run from a docked terminal, its watcher reopens the app with `open`, and macOS passes that shell's environment straight through (verified: ppid 1, full marker set present). Claude Code in every new terminal then saw `CLAUDE_CODE_CHILD_SESSION` from a session that had already ended, took itself for a nested child and turned transcript saving off. `dropInheritedAgentSession()` deletes those markers once, at startup before anything can spawn, which is why no spawn site needs to know about it. Its list is **explicit, never a `CLAUDE_*`/`CLAUDE_CODE_*` wildcard**: real configuration shares those prefixes (`CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_USE_BEDROCK`/`_USE_VERTEX`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`), and quietly dropping a user's Bedrock or config-dir setting is a worse failure than the warning it would prevent — a missing marker costs one warning, a deleted config var costs a broken install.
- **Quitting must kill the ptys, and only `before-quit` sees a quit.** Cmd+Q — and every `app.quit()` — closes the windows itself and goes straight to `will-quit`; `window-all-closed` is **not** emitted (measured: `before-quit -> will-quit`). With `ptys.killAll()` hung only on the latter, every normal macOS quit left node-pty sessions alive into `node::FreeEnvironment`, where the exit-callback thread fires its ThreadSafeFunction into a dying env and napi throws a C++ exception with no JS to throw it into — `abort()`, a SIGABRT crash report each quit, and a `will-quit` that never completes. Both handlers stay: `window-all-closed` is the non-macOS "last window closed" path.
- **node-pty `spawn-helper` needs the exec bit.** npm strips it on extract → every spawn fails with `posix_spawnp failed`. `scripts/copy-vendor.js` (postinstall) restores it; `build.asarUnpack` keeps node-pty outside the asar so packaged builds can exec it too.
- **Views belong to the workspace.** Web tabs are *instances* (`wsViews().tabs`, several of one provider allowed), opened from the `+ web` menu on the workspace strip and persisted in `views.json`; each becomes a pane. Terminals carry `wsId`, and `mountLeaf` mounts a `term` leaf **only** when that terminal belongs to the space being applied — the same ownership check the `web` branch does against `V.tabs`. Both are load-bearing: a term leaf references `state.termSeq`, a per-run counter, so `adoptLeafSeq` must also raise it past every persisted ref or the first terminal of the next run takes a number another space's stale leaf still points at, and that space silently displays this space's agent. `showWorkspaceViews()` runs on every workspace switch/add/remove and calls `applyTiles()`, which hides every pane not in the active space's tree. Other spaces' webviews and PTYs stay alive in the background. Never show a view from another workspace.
- **Groups are the space's virtual desktops.** Each space owns `groups: [{id, name, tree, focus, zoom}]` + `activeGroup`; `groups()` migrates and repairs that list, and `tiles()` returns the *active* group — which is why every tree edit below is group-agnostic and needs no changes. Switching a group just applies its tree: the other groups' webviews and PTYs stay alive and hidden, exactly like another space's panes. Closing a group routes each leaf through `closePane` so nothing leaks as an unreachable instance, and the last group can't be closed. UI is `#group-bar` (`renderGroupBar`, chips + `+`), keys are Cmd/Ctrl+Alt+1…9. Anything that walks persisted trees must use `groupsOf(V)`, never `V.tiling`.
- **Layout = a tiling tree, per group (`tiles() = {tree, focus, zoom}`, persisted in `views.json`).** Web views, terminals and the files tree are all equal **panes** (leaves) in one binary tree per space; there are no docks and no global tab strip. The pure engine is `src/renderer/layout.js` (`window.TileTree`, also `require`-able) — tree edits, `rectsFor`, `dividersFor`, `clampRatio`, geometric `neighbour`, and `migrate` from the old dock layout — covered by `npm test` (`scripts/test-layout.js`, no framework). `applyTiles()` in `app.js` turns the tree into rects and applies them; `openPane`/`closePane`/`focusPane`/`toggleZoom` are the entry points. Opening a pane splits the focused one along its longer axis (dwindle).
- **The files tree is a dock, not a tile.** `openFilesPane()` uses `TileTree.insertRoot` to put it against the whole left edge at `wsViews().filesRatio` (remembered per space by `rememberFilesRatio` on close, so it reopens at the width you left it). Two rules keep it a sidebar rather than a tile: `splitTarget()` never splits the files pane while a content pane exists, and `openPane` docks the first content pane to its *right* instead of halving it. Opening the dock does not steal focus, so the next pane still lands in the content area. Vocabulary: **space** = project workspace, **pane** = a tile — never "window" or "workspace" for tiling.
- **`#tiles` is FLAT and a pane element is created once per content instance.** A pane's DOM node is a direct child of `#tiles`, built once per web tab / pty / files tree, and **never reparented** — a tree edit changes which *rect* an element receives, never which parent it has. This is load-bearing, not stylistic: reparenting a `<webview>` detaches its guest and reloads the page, destroying scroll position and unsent chat drafts, silently and without throwing. Measured both ways in a spike (`docs/superpowers/specs/2026-08-18-tiling-layout-design.md`) and re-confirmed in the running app: 6 live webviews survived 60 divider resizes plus a pane swap with page state intact. Never write `someContainer.appendChild(paneEl)`.
- **A file is a pane, and a doc leaf's ref is an instance — never a path.** Leaf kind `'doc'` (deliberately not `'file'`: the dock kind `'files'` already exists, and one character between two string compares is a bug waiting to happen). Instances live per space in `views.json` beside `tabs` — `docs: [{id, path, mode}]` — and **only those three fields persist**: an unsaved buffer never reaches disk, and a restart re-reads from the file. The ref is an instance id because a plain click *retargets* the doc pane you already have: `doc.path` changes and the pane's body is rebuilt, so the tree is never edited, focus never churns and the ratio you dragged survives. Cmd/Ctrl-click opens a second pane instead. `mountLeaf` returns `null` for a `doc` leaf whose instance is gone, which prunes a stale leaf through the contract already there; `closePane` owns the dirty prompt and calls `closeDocInstance`, and its trailing `else` is now an explicit `else if (lf.kind === 'files')` — it used to mean "anything not web or term".
- **Rendered markdown is built with `createElement`, never `innerHTML`.** `src/renderer/markdown.js` is a pure `parse(text) → blocks[]` (dual-exported like `layout.js`, covered by `scripts/test-doc.js`) and `renderBlocks` in `app.js` turns those tokens into DOM. Two parser rules are what make this safe by construction rather than by a sanitiser staying correctly configured: raw HTML never passes through (a `<script>` line in a downloaded README renders as literal text), and hrefs are filtered at parse time to `http:`/`https:`/`mailto:`/relative, so `javascript:` and `data:` degrade to plain text. A relative image is fetched back through `readDoc` — `resolveSafe` guards it and the CSP needs no `file:` relaxation. Don't swap in a markdown library without bringing both rules with it.
- **`readDoc` is the one channel that classifies and reads a file.** `docKind()` in `workspace.js` decides `md`/`text`/`image`/`pdf`/`binary` from the extension, and the *tree nodes carry it too*, so the tree and the pane can never disagree. Caps live there as well: 2 MB text, 25 MB image, PDFs uncapped because they are handed a `file://` URL for a `<webview>` rather than copied into base64. SVG is an `image` that also carries its `text` — that is what gives it the same `src`/`view` toggle markdown has. `extOf()` exists because `path.extname('.gitignore')` is `''`, so `TEXT_EXT`'s dotfile entries could never match through `extname` alone.
- **A doc pane re-reads its own file; the watcher ping carries no path.** `recheckDocs()` runs on `workspace:changed` and on every space switch (the watcher only ever binds the *active* space's root). A clean pane takes the new content and keeps its scroll; a dirty one gets the `changed on disk` bar, where **"keep mine" sets `stale`** so the next save may overwrite the newer file without asking again. A save needs no suppression flag: afterwards the disk matches `savedText`, so the tick it causes is a no-op.
- **Pane keybindings live in one `keydown` listener at the bottom of `app.js`** (`MOD` = Cmd+Alt on macOS, Ctrl+Alt elsewhere): arrows focus the geometric neighbour, Shift+arrows `moveLeaf` the focused pane to that edge, `1`…`9` switch group, `F` zooms, `W` closes, `E` flips a markdown/SVG doc pane between `src` and `view`. Plain Cmd/Ctrl+S saves the focused doc pane — a different modifier shape, in the same listener. Ctrl+` is separate — it focuses the first `term` leaf, or creates one if the space has none. Adding a shortcut means editing that listener, not the tree module.
- **Keyboard focus is restored into the focused pane; the `focused` class is only a border.** `focusPaneContent(lf)` in `app.js` is the one place that puts DOM focus inside a pane, per kind: `term.focus()`, the webview host (blurred first when it already is `document.activeElement`, because `focus()` is then a DOM no-op and Electron's guest page stays unfocused), or a doc pane's `textarea.doc-src`. It runs from `focusPane` **even when the leaf is unchanged**, from `showWorkspaceViews()` and `switchGroup()` (a pane hidden with `display:none` drops its focus, and a click on the workspace strip lands it on `body`), and on `win:focus`, which main sends from `win.on('focus')` — the renderer's own `focus` event is ambiguous once a webview guest holds focus. Without all three, coming back to Tote or to a space needs a second click before typing works. A click inside a webview never reaches the pane's mousedown (the guest eats it), so the host's `focus` event is what moves the logical focus to that leaf — guarded on `tiles().focus !== leaf`, since `focusPane` on a web leaf re-focuses that very element.
- **Divider and pane drags must add `body.dragging`** (sets `pointer-events: none` on webviews) or the guest view swallows `mousemove` mid-drag.
- **`archlens.model.yaml` lags `src/`.** It is a tracked, hand-maintained component/method model (one entry per file under `src/`, consumed by the archlens MCP tools) — regenerate or extend it when adding a module, or the model quietly under-reports the renderer. `layout.js` and `markdown.js` were both added by hand after the fact.
- **Shift+Enter must reach the agent as LF.** xterm emits a bare `\r` for Enter and Shift+Enter alike, so a TUI agent cannot tell them apart and treats both as "send". `spawnTerm` installs an `attachCustomKeyEventHandler` that writes `\n` (0x0a) instead — the byte **Ctrl+J** produces, which is the newline Claude Code and Codex accept with no per-terminal setup step. ESC+CR was the first attempt and is wrong: Claude Code reads it as "escape, then send". Don't drop it when touching terminal setup. The same handler owns the scrollback keys for the same reason: a bare Up/Down is the agent's prompt history, so **Shift+arrows** (line) and **Shift+Home/End** (ends) scroll the xterm viewport instead, and pass through untouched on the alternate screen, where there is no scrollback. Shift+PageUp/PageDown stay xterm's own bindings. The handler also hands **Alt+Up/Down** back to the agent: on every platform but macOS xterm rewrites `ESC[1;3A` into `ESC[1;5A` (Ctrl+Up, a readline hack in its `Keyboard.ts`), so Codex's "alt + ↑ to answer" queued questions could never be opened on Linux or Windows — we write the standard sequence ourselves.
- **A dropped file must never reach Chromium.** An unhandled file drop navigates the window to `file:///…`, replacing the whole UI with the dropped file. Three layers keep that from happening and all three must stay: `acceptFileDrop()` on each terminal pane types the shell-escaped path into the PTY (no trailing newline — *sending* stays the agent's decision), window-level `dragover`/`drop` handlers swallow every other drop, and `will-navigate` on `win.webContents` in `main.js` is the backstop. Paths come from `webUtils.getPathForFile` via `tote.filePath`; `File.path` was removed in Electron 32 and returns `undefined` here.
- **A hidden terminal measures zero, and xterm caches that.** A pane in another group or space is `display: none` but its pty keeps streaming, and xterm sizes its scroll area as `round(rowHeight * bufferLength) + (viewportHeight - canvasHeight)` — so every write while hidden re-records a scroll area one whole viewport too short. Nothing recomputes it on the way back: `syncScrollArea` watches the buffer length and the cell height, neither of which changes by becoming visible, and `fit()` is a no-op without a dimension change. The user gets two symptoms that are one bug — dragging to the bottom stops short of it (~21 lines on a 500-line buffer), and a viewport short of the bottom makes xterm stop following, so output streams into a view frozen on old content until a keystroke happens to scroll to the bottom. `refitTerms` therefore tracks `wasHidden` per terminal and calls `repairViewport` on the way back, which forces the re-measure through `term._core.viewport.syncScrollArea(true)` — private, hence guarded. It moves no scroll position, so a pane left deliberately scrolled up stays put.
- **Terminal size race**: `spawnTerm` fits xterm synchronously *before* `ptySpawn` and pushes `ptyResize` right after — the PTY must be created at the real size, not 80×24. A `ResizeObserver` on `#term-container` refits on any layout change.
