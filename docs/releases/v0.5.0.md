# Tote 0.5.0 — release candidate notes

This version is prepared in source. These notes do not mean a signed release has been published.

Desktop source uses Electron 45.3.3 and requires macOS 13+ or a supported 64-bit Windows/Linux system. Building from source requires Node 22.12+. Provider cookie/popup/download routing has an isolated integration test; real provider login and physical upgrades remain release checks.

Android now requires Android 13+ (API 33). Production APKs use a dedicated key and proof of rotation from the published development identity, preserving the upgrade path without retaining a legacy Android signing route. Emulator upgrade/data-retention checks pass; physical phone verification remains pending.

Desktop and Android now use one release version. This release includes safer configuration writes and recovery, shared-layout conflict handling, synchronized terminal dimensions and mobile colors, bounded remote output with reconnect/replay, and desktop/Android diagnostics with reviewed exports.

Settings → About on desktop and Updates on Android can check the public GitHub release endpoint on demand. Tote does not install updates or restart automatically. Desktop delays its update download action while any host terminal is alive; phone drafts must be saved or cleared before following an update link. Save documents before closing the desktop. Host processes now run independently and survive desktop quit/crash; packaged hosts retain a separate runtime copy while the UI is replaced. Settings → About provides host status, start/stop and opt-in sign-in startup. Finish agents before stopping or upgrading the host; reboot and sign-out still end its processes. See [background host operation](../background-host.md).

Wire protocol v1 remains compatible with earlier Tote hosts/viewers. App version differences are reported without rejecting otherwise compatible sessions. Feature support is negotiated separately: older hosts may lack shared layout revisions, output acknowledgements or diagnostics. A wire protocol mismatch refuses connection with update guidance.

Production release scope is Linux AppImage/deb/pacman and Android APK first. Preview packaging also produces a macOS DMG for the runner's native architecture and Windows x64 NSIS; those remain outside the production channel until signing and verification are ready. The bundle includes SHA256SUMS and release-manifest.json. Preview builds have no desktop publisher identity (macOS uses ad-hoc signing for launch) and a debug-signed Android APK; they are separate from production signing. Signed tag builds create a **draft**, which remains excluded from update notices until published.

Signing credentials and physical-device verification must be completed before publishing. Use the pinned Android production identity and approved proof of rotation: an unrelated key cannot replace an existing installation. Do not uninstall a working installation just to bypass a key mismatch; preserve its local data and resolve the signing configuration first.

- Add explicit, verified in-app updates for Linux AppImage and Android. Downloads can be canceled and recovered after restart; installation guards unsaved work and preserves the background host. Package-managed desktop installs retain manual guidance. Install this first updater-capable release manually; future compatible published releases can use the new flow.
