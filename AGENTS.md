# Tote — agent notes

Electron hub app: web LLM tabs + shared workspace folder + docked CLI-agent terminals.

- Run: `npm install && npm start` (postinstall copies xterm assets to src/renderer/vendor).
- **Host / viewer split** (devices design, `docs/superpowers/specs/2026-10-12-devices-design.md`): `src/host/` owns the device — spaces, files, `views.json`, terminals, watchers — and never requires `electron` (`npm test` enforces it). Every window is a viewer with its **own** active space; `host.call(name, viewerId, args)` runs a method from `host.js`'s table with `ctx = { viewer, wsId }`, and file ops go through `workspace.scoped(wsId)`. Terminals are host sessions (`src/host/sessions.js`): a pty plus an `@xterm/headless` mirror that replays to a late window, answers terminal queries once (windows drop their own replies via `src/renderer/termreports.js`), and survives its window closing. `src/host/channels.js` classifies every IPC channel as host / viewer / split.
- **Devices** (phase 3): with `settings.shareDevice` on, `src/host/server.js` listens on this node's Tailscale IP only and admits a caller only when `tailscale whois` says it is one of the same owner's own nodes (not shared in). Another machine's Tote then calls host methods over JSON-over-WebSocket (`src/host/protocol.js`) exactly as a window does over IPC; `src/main/devices.js` is the client, and `route()` in `main.js` sends a window's host calls to whichever device it is viewing. The device chip at the top of the sidebar lists your devices and switches without reloading — the renderer keeps one slice of `state` per device (`SLICE`, `switchDevice`), events carry the device key, a dropped device keeps its panes under a banner and reconnects by itself, downloads and PDFs cross between machines in slices; things that need this machine's disk or apps refuse while viewing another.
- Main process: `src/main/` (sessions per provider partition, downloads → the inbox of the space the downloading window is in, Downloads-folder bridge for native apps (macOS only; copies, and only files the quarantine xattr attributes to a known LLM app), app launcher, IPC, node-pty). Setup wizard logic lives in `src/main/installer.js` (system checks, Claude Desktop MCP binding, MCP snippet) + the `#wizard-*` section of `src/renderer/app.js`.
- CLI profiles carry an `install` command (npm -g) used by the wizard; keep package names accurate when adding profiles. Wizard installs self-heal: the run's output is buffered and `src/renderer/npmfix.js` (pure, `npm test` covers it) detects npm's blocked-install-scripts warning (retry with `--allow-scripts=…`) and EACCES on a root-owned global prefix (`setup:fixNpmPrefix` points npm at `~/.local` only when `prefixPlan` says that's safe); each mend runs at most once.
- **Remote spaces**: a space with a `host` field lives on another machine over ssh (typically Tailscale SSH). `New remote space` in the sidebar creates one; `src/main/sshfix.js` is pure (quoting, every remote command, containment, the ssh/Tailscale detectors — `npm test` covers it) and `src/main/remote.js` holds `RemoteConn` + `RemoteFs`. Rules that matter: never `expandTilde` a remote path or `mkdir` its inbox locally; `discardTemp()` refuses remote outright; `shq()` is the *only* thing that puts a path into a remote command; every non-interactive op sets `BatchMode=yes` and hands failure to the connection actor, which owns the one interactive pty allowed to authenticate; BatchMode alone does NOT prevent a hang (Tailscale's check is served after the connection is up, so ssh holds the session open) -- `exec()` in remote.js bounds every op with a timeout plus a stderr sniffer (`needsHuman`) that aborts the instant the auth banner appears; the master socket uses `ControlPersist=yes` and deliberately outlives Tote, because its lifetime is what sets how often Tailscale's periodic check makes the user re-authenticate. Re-auth is ambient, not a setup step — it surfaces as a banner in the files pane and a connect *pane*, never a modal. A remote space polls a remote-hashed fingerprint instead of binding chokidar.
- Workspaces are two-level: one `global` + project spaces in `config/workspaces.json`. All file ops resolve the CALLING WINDOW's space at call time via `host.ws(ctx)` (a `workspace.scoped(wsId)` view) — never cache the root; the registry's `active` is only where a fresh window opens. Spaces are managed from the sidebar's right-click menu and the Workspaces section of Settings (add / rename / change folder / remove → `workspaces:*` IPC); ids are stable across rename/re-point.
- Renderer: `src/renderer/` vanilla JS, no bundler. Bridge surface = `window.tote` (see `src/preload/preload.js`).
- Providers, CLI profiles, workspaces and apps are **data**, not code: defaults in `config/*.json`, runtime copies in userData. Prefer adding entries there over hardcoding.
- Runtime JSON writes go through `ConfigStore`: flushed sibling temp + atomic rename, with a validated previous version in `.bak`. Reads recover invalid/missing primary files while preserving corrupt evidence; an unusable primary and backup must fail visibly, never reset silently. `scripts/test-config.js` exercises failure and crash recovery on all three desktop platforms in CI. Unchanged saves retain the previous distinct version; validate top-level structure as well as JSON syntax.
- Never give the renderer `nodeIntegration`. New capabilities: classify the channel in `src/host/channels.js`, then a host method in `host.js` (forwarded by name) or an ipcMain handler in `main.js` (viewer/split), then a preload wrapper.
- Keep all workspace file access inside `WorkspaceManager.resolveSafe` (path-escape guard).
- **The tree watcher has a file-descriptor budget and blowing it breaks terminals, not the tree** (chokidar 4 has no fsevents, so it opens one fd per watched path). A terminal that prints `[process exited with code 0]` and nothing else means the main process is out of descriptors, not that the shell failed. Defences: `IGNORE` by name, `IGNORE_UNITY` + `skipper()` by context (`Library`/`Temp`/`Logs`/`obj` are pruned only inside a real Unity project, since those names are also real source dirs), `watchPlan()` lowering the depth to fit `WATCH_BUDGET`, and `watch()` awaiting the previous watcher's `close()` before binding the new one — it re-arms on every space switch.
- Terminals must stay real PTYs (node-pty) — piping through child_process breaks TUI agents. A remote terminal is still a real local pty with `ssh -tt` inside it, riding the space's master socket through the *remote* login shell, so xterm, resize and the key handlers are untouched. node-pty's prebuilt `spawn-helper` must be executable (postinstall chmods it; asarUnpack for packaged builds) or spawns fail with `posix_spawnp failed`.
- Tote hands `process.env` to every child (ptys, wizard installs, `cli:check`, local services), so `dropInheritedAgentSession()` in `environment.js` strips inherited *agent-session* markers (`CLAUDE_CODE_CHILD_SESSION`, `CLAUDECODE`, …) at both viewer and host startup — an upgrade reopened from a docked agent terminal otherwise makes every new terminal look like a nested child session (Claude Code then disables transcript saving). Keep that list explicit; `CLAUDE_CONFIG_DIR` and the Bedrock/Vertex vars share the prefix and must survive.
- A GUI launch (Finder/Dock/`.desktop`) gives the app a minimal PATH, so `codex`/`claude`/`npm` are missing even though they work in a terminal. `ptyManager.js` runs every CLI profile through `$SHELL -l -i -c 'exec …'`, and `adoptLoginShellPath()` in `main.js` adopts the login shell's PATH at startup for the wizard checks and local services. Don't exec profile commands directly on POSIX.
- Webview popups (OAuth) must open in-app so they share the provider partition; only non-http schemes go to the system browser. UA = Electron's real UA minus Electron/Tote tokens — never a hardcoded foreign UA.
- Views are per-workspace: web tabs are instances stored in `views.json` (`+` menu opens providers, duplicates allowed), terminals tagged with `wsId` and referenced by host session id (random, chosen by the renderer); `showWorkspaceViews()` restores a space's setup on switch. `src/host/views.js` supplies content revisions through `views:snapshot` and validates per-workspace `views:patch` changes. `viewsync.js` queues snapshots/saves per device, keeps conflicting drafts local, and requires explicit resolution. `views:changed` triggers a fresh snapshot; `reconcileViews()` preserves pane identity and dirty docs block removal/retargeting. Capture the device in every layout RPC, never from state at debounce time. Legacy whole-map saves are diffed against that viewer's last read and still checked; older hosts are layout-read-only for new viewers. `npm run test:layout-sync-ui` exercises real renderers and rapid device switches.
- Layout: a **tiling tree of panes**, not docks. Web views, terminals and the files tree are equal leaves in one binary tree; the pure engine is `src/renderer/layout.js` (`window.TileTree`, covered by `npm test`) and `applyTiles()` in app.js turns the tree into rects. `#tiles` is flat: a pane element is created once per content instance and **never reparented** — reparenting a `<webview>` reloads the guest and loses page state.
- **Sidebar order** is the registry list order; a tab drag calls `workspaces:reorder` → `WorkspaceManager.reorder(ids)`, which only rewrites the order in `workspaces.json` (active space, entry fields and watchers untouched) and re-appends any id the renderer omitted.
- **Temp spaces** carry `temp: true` + `lastUsed` and live under `settings.scratchRoot` (default `~/tote/scratch`). `discardTemp()` is the only function in Tote that deletes user files — temp-only, inside-the-root-only, never the last space — and `remove()` still never touches the disk. `promote()` moves the folder and keeps the id so `views.json` survives; the sweep runs at launch only. Pure parts are in `src/main/scratch.js`, tested by `scripts/test-scratch.js` (run by `npm test`).
- Each space holds **groups** — virtual desktops with their own tree (`views.json`: `groups[]` + `activeGroup`), switched from `#group-bar` or Cmd/Ctrl+Alt+1…9; `moveToGroup()` moves a pane between them (drag the head onto a chip, right-click the head, or Cmd/Ctrl+Alt+Shift+1…9) by editing trees only — nothing is reparented. Other groups' webviews and PTYs stay alive and hidden. Walk persisted trees with `groupsOf(V)`, never `V.tiling`.
- The files tree is a **dock**: `insertRoot` pins it to the whole left edge at the width it had when closed (`filesRatio`, per space); `splitTarget()` and `openPane` keep content panes out of it.
- Files dropped on a terminal pane are typed in as shell-escaped paths (`acceptFileDrop`), never sent — and every other drop is swallowed, because Chromium's default is to navigate the window to the file. Paths come from `webUtils.getPathForFile` (`File.path` is gone since Electron 32), with `will-navigate` in main.js as the backstop.
- **Files are panes**: clicking one opens leaf kind `doc`, whose ref is an *instance* (`views.json`: `docs: [{id, path, mode}]`), not a path — a click retargets the pane you have, Cmd/Ctrl-click opens a second. Only those three fields persist; unsaved buffers never reach disk. Text and code are editable with Cmd/Ctrl+S, markdown, HTML and SVG render with a `src|view` toggle (MOD+E) — HTML in its own `<webview>`, so the page's own CSS/JS/images load — images and PDFs are read-only, and anything else still goes to the system app. `readDoc` in `workspace.js` is the single classify-and-read channel; `docKind` also stamps every tree node.
- Rendered markdown comes from `src/renderer/markdown.js` (pure, `npm test` covers it) and is built with `createElement` — **never `innerHTML`**. The parser keeps raw HTML literal and filters hrefs to http(s)/mailto/relative, which is what makes that safe; keep both rules if you ever swap the parser out.
- A doc pane re-reads its own file on `workspace:changed` (the ping has no path): clean panes reload silently, dirty ones show the `changed on disk` bar, and "keep mine" lets the next save overwrite.
- The `focused` class is only a border: `focusPaneContent()` puts real keyboard focus inside the focused pane (xterm, the webview host — blurred first if it already is the active element, or Electron's guest stays unfocused — or a doc textarea). It runs from `focusPane` even when the leaf is unchanged, after every space/group switch, and on `win:focus` from main; drop any of those and the user needs a second click before typing works. Clicks inside a webview never reach the pane, so the host's `focus` event is what moves the logical focus there.
- Any splitter or pane drag must toggle `body.dragging` so webviews don't eat mouse events. Fit xterm before `ptySpawn` and `ptyResize` after, or TUIs render at 80×24. Shift+Enter needs the `attachCustomKeyEventHandler` in `spawnTerm` that sends LF (`\n`, the Ctrl+J byte) — xterm's default CR is indistinguishable from Enter, so agents submit instead of adding a line. That handler also maps Shift+arrows/Home/End to xterm's scrollback (bare arrows belong to the agent's history), passing them through on the alternate screen. It also sends Alt+Up/Down as `ESC[1;3A/B` itself — xterm turns them into Ctrl+arrow on non-macOS, which hid Codex's "alt + ↑ to answer" prompt.

- **Navigation sidebar**: `#ws-bar` is the left grid column (230px, 62px collapsed). `#group-bar` is moved after the active workspace row; never move panes. Workspace reveal/drag scrolling uses vertical coordinates. Collapse is a renderer-local preference (`tote.sidebarCollapsed`); `#tiles` ResizeObserver handles pane layout and terminal refits. `npm run test:sidebar-ui` runs an isolated Electron renderer with a fake host to check navigation and layout.

- **Shared terminal dimensions**: `pty:data` carries `cols`, `rows` and viewer-specific `controlsSize`; session metadata advertises `sizeSync`. The host serializes output, resize barriers and replay through the mirror parser. Desktop focus/input claims sizing control (`pty:resize` with `claim: true`); automatic layout requests use `claim: false` and only the current controller can resize. Passive viewers render the host grid and scroll; do not fit their xterm independently. `termstream.js` queues writes, resize and replay for desktop and mobile; bypassing it can parse old bytes at a new width. `npm run test:terminal-ui` checks two actual desktop renderers with different window sizes.
- **Remote output consumption**: `src/host/transport.js` bounds queues/calls and enforces heartbeat/parser deadlines. `flow: 1` hello negotiation enables exact-frame `ack` messages after xterm parsing. Desktop delivery tokens return through the viewer-only `devices:outputAck`; Android returns `termStream.write()` from `hostEvent` and acknowledges native bridge delivery through `received`. Preserve these promises, or slow viewers can bypass flow control. On overload detach/close only that viewer, then replay the host mirror on reconnect; never pause a shared PTY for one viewer or retry input. A replay supersedes queued stale output only after active parsing finishes. See `docs/device-transport.md` and `scripts/test-transport.js`.

- **Android client**: `mobile/` is a separate Capacitor app (no local host). `npm run mobile:apk` builds after `npm ci --prefix mobile`; JDK 21 + Android SDK 36 required. It uses native WebSockets restricted to Tailscale IPv4, the existing host protocol, and native SpeechRecognizer. Keep group/pane selection local; never save mobile layout into desktop `views.json`. Attach preserves host PTY dimensions; resize only on explicit Resize terminal. Mobile navigation is a side drawer (`mobile/src/navigation.js`); the default phone-only wrapped text view (`reading.js`) reads xterm’s parsed buffer without changing the host PTY or trusting raw HTML. Import the terminal-report filter as a module in the mobile bundle, not through `window.TermReports`. Reconnect must never retry input. `npm test` includes its protocol/model checks; `npm run test:mobile-ui` uses a fake host/speech service in an isolated renderer. See `mobile/README.md` for physical-device verification limits.

- **Mobile discovery**: with Share device on, `src/host/discovery.js` sends bounded UDP connection hints over Tailscale to the same owner's online Android peers (port 47822); no LAN multicast. Android receives briefly in the foreground, accepts only matching Tailscale source/address hints, and verifies each with an authenticated protocol `probe` before saving. The phone never serves files/terminals. `device:peers` returns only own Tailscale peers for further probes. Stop announcements when sharing stops and receivers when backgrounded. No Wi-Fi, QR or manual address bootstrap is required. `scripts/mobile-discovery.js` is a temporary bridge for a running older desktop, preserving its sessions.

- **Diagnostics**: `src/shared/diagnostics.js` is the allowlist shared by host, desktop and Android. Never export arbitrary logs: categorize errors on capture and discard their text. `device:diagnostics` is host metadata; transient session IDs are used only to associate viewports and removed by the final sanitizer. Desktop `diagnostics:get`/`diagnostics:export` are viewer-only; Android saves the reviewed snapshot through ACTION_CREATE_DOCUMENT. Keep the preview/export identical, bounded (64 terminal rows, 50 errors, 64 KiB), and label cached or unsupported host data. No terminal output, private paths, addresses, tokens or cookies.

- **Releases**: `release.json` is authoritative; `releasePlatforms` selects production targets (currently Linux/Android), while previews always exercise all platforms. `npm run release:preflight` checks exact-commit CI and signing configuration names/rules without reading credentials. `npm run release:version` updates package/lock versions, Android reads it directly, and `release:check`/beforePack enforce consistency. `src/shared/updates.js` owns pure stable-release and protocol/version policy. Update checks use only the fixed public GitHub HTTPS endpoint, on request, bounded and cached; never trust remote download URLs. No automatic host replacement/restart while host sessions are running; update guidance still defers manual installation for active sessions. `.github/workflows/release.yml` builds previews on packaging PRs, requires configured credentials for production signing, verifies packaged PTYs/signatures/checksums, and creates drafts only on matching tags. Never publish debug/unsigned previews as signed releases. See `docs/releases.md`.

- **Dependency maintenance**: `.github/dependabot.yml` proposes npm/Gradle/action updates; `dependencies.yml` blocks new high/critical PR advisories and reports existing debt weekly. `npm run dependencies:report` audits both full lockfiles (Electron is a devDependency but shipped) and checks current supported Electron lines. Failures/offline evidence must not become a clean report. Major runtime changes need packaged PTY checks and the provider/download/mobile verification in `docs/dependencies.md`; keep upgrade decisions there and the WebContentsView migration in #2 separate.

- **Background host**: `src/host/daemon.js` runs under plain Node or the packaged Electron binary in Node mode, without importing Electron. `runtime.js` owns workspace/PTY/watcher/sharing lifecycle; the desktop uses `src/main/localHost.js`, one authenticated local connection per window. The profile-derived loopback port is a singleton gate and binds before config is opened; collisions fail closed. The private bearer stays in the main process, never a renderer/URL. Local admin methods are separate from the remote allowlist; reject browser Origins. Local output must receive renderer consumption acknowledgements too. Never retry input or spawn a replacement host from a reconnect loop. `hostInstall.js` keeps immutable runtime copies for packaged hosts; never overwrite/remove a running copy. Quit kills only viewer setup PTYs; explicit Stop host confirms live agents. Sign-in startup is opt-in; host crash, sign-out and reboot end PTYs. `npm run test:background-ui` tests real desktop quit/crash/relaunch, and packaged smoke tests boot the copied runtime. See `docs/background-host.md`.
