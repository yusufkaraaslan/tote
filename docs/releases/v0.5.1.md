# Tote 0.5.1

Fixes opening DeepSeek Harness (DSH) inside Tote when its local web server requires a startup login token.

## What changed

- Opening a local web provider now checks its server and invokes its configured startup command when needed. Concurrent opens share one startup attempt, with retry controls and visible failure messages.
- The default DSH command binds to `127.0.0.1:3080`, suppresses an external browser launch, and passes the printed startup login URL into Tote's provider pane. Only the unchanged original DSH defaults are upgraded; custom commands and addresses are retained.
- For DSH already running in a terminal, paste its complete `dsh web:` startup URL into the pane's **Connect URL** field. Tote has its own browser session, so a login in another browser does not authenticate the Tote pane. Startup tokens are not saved in provider settings or workspace layouts.
- Local web panes include startup status and retry controls. Starting a local service is refused while viewing another device.

## Upgrade

From Tote 0.5.0, use **Settings → About → Check for updates → Download → Install** on Linux AppImage. The desktop viewer reopens while the existing background host and agent sessions continue running. This fix does not require replacing or restarting the host, and it does not update or restart an already-running DSH process.

Android uses the existing in-app update flow, requires Android 13+, and advances to versionCode 13 with the same production signing identity and lineage. There are no Android behavior changes in this patch. Wire protocol v1 is unchanged. Package-managed Linux installations retain their package-manager update path.

## Verification

Automated regression coverage includes local service reuse, concurrent startup, complete token capture, startup failures/timeouts, configuration migration, and real Electron provider authentication through a temporary startup URL. The existing full validation and release packaging checks cover desktop/mobile behavior, packaged PTYs, background-host reconnect, and Android signing.

The reported failure was reproduced against a running DSH server: the configured loopback address returned HTTP 401 without its startup token. The authenticated connection flow was verified with an isolated local fixture; this does not claim a new end-to-end live DSH chat or physical Android installation test.

Release downloads include `SHA256SUMS` and the production `release-manifest.json` required by the updater. Linux publisher trust comes from the fixed GitHub HTTPS origin plus checksums; the Android APK uses the pinned production certificate and approved signing lineage.
