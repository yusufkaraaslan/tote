# Tote 0.5.7

Android can open provider websites, and terminals started on the phone now appear in desktop Tote automatically.

## What changed

- **⋮ → Open web** opens a provider or an HTTP(S) address in an Android browser tab. Existing provider panes have an Open button. The browser uses the phone's login; closing it returns to Tote with terminal drafts preserved. Desktop cookies and the desktop's current chat page are not transferred.
- Computer-local addresses such as `127.0.0.1:3080` explain why they cannot open from a phone. DSH still needs a URL reachable over Tailscale; this release does not expose local services automatically or store startup links.
- Desktop viewers discover live terminals missing from the shared layout and place them in their workspace's active desktop group. This reuses the running PTY without restarting it or claiming its size. Concurrent desktop viewers use revision checks to avoid duplicate panes or overwriting layout edits.
- Mobile follows a newly placed terminal into its desktop group, preserving the selected session and unsent draft. Workspace tools close after choosing an action to keep the terminal visible.

## Upgrade

Update desktop through **Settings → About → Check for updates → Download → Install** and Android through **Updates → Check for updates → Download → Install**. Both viewers need 0.5.7 for these changes. The background host can stay running with its agents; the terminal fix uses existing protocol-v1 methods. Android advances to versionCode 19 with the same production signing identity and lineage.

## Verification and limits

Unit tests cover placement, workspace/group preservation, legacy layouts, concurrent viewers, conflict handling, selection migration and web URL validation. Real desktop renderers verify one shared pane per session, attachment without spawning or resizing, and existing layout/draft conflict behavior. The Android renderer checks web actions, browser failures, draft preservation and following a phone-created session into its desktop group. Android compilation, unit tests and lint check the native browser integration.

Physical phone provider login and browser-return checks remain unverified. Native browser integration uses the official Capacitor Browser plugin; no arbitrary page is loaded into Tote's privileged app WebView.
